# תוכנית – Milestone 4: היסטוריית משחקים ומחיקה מאושרת

מקורות: `MILESTONES.md` (Milestone 4), `PRD.md` §4.4 ומקרי קצה, `ARCHITECTURE.md` §2.5 (מודל נתונים), §2.6, ADR-4 ו-ADR-5, `DESIGN.md` §1.2, §1.3 וה-Style Guide (History Cards, Dialog).
מצב פתיחה: Milestone 3 ✅. מסך "אודות" מציג חיווי ריק קבוע; שום דבר לא נשמר.

## 1. מה נבנה

כל משחק שמסתיים (ניצחון או הפסד) נרשם פעם אחת ב-`localStorage` ומוצג במסך "אודות" ככרטיס: תאריך ושעה, מספר שלבים שהושלמו ו"ניצחון"/"הפסד" (בטקסט, לא בצבע בלבד). נשמרים עד 10 משחקים, מהחדש לישן. כשיש רשומות מופיע כפתור "מחק היסטוריה" שפותח חלונית אישור ("ביטול" / "מחק"). כשל באחסון לא חוסם משחק, ומוצגת הודעה בעברית.
**לא בשלב זה:** PWA ו-Offline (Milestone 5). אין שינוי בלוגיקת המשחק עצמה.

## 3. מודול האחסון (`historyStorage.ts`)

- טיפוסים לפי ARCHITECTURE §2.5: `GameResult { id, finishedAt (ISO), completedRounds 0–10, outcome 'win'|'loss' }`, `HistoryData { schemaVersion: 1, results }`.
- `loadHistory()` ← `{ ok: true, results } | { ok: false, results: [] }`. מפתח חסר = רשימה ריקה והצלחה. JSON פגום / גרסה לא מוכרת / `localStorage` זורק ← `ok: false`. רשומות לא תקינות מסוננות; חותכים ל-10.
- `addResult(result)`: קורא את הקיים (פגום ← מתחילים מרשימה ריקה תקינה), מוסיף בראש, חותך ל-10, כותב. מחזיר את הרשימה החדשה או שגיאה.
- `clearHistory()`: מוחק את המפתח (או כותב רשימה ריקה). שגיאה ← מחזיר כשל, בלי להעמיד פנים שהצליח.
- `createResult(state, now)`: בונה רשומה מ-`status` ו-`completedRounds`; `id` מזמן + מספר אקראי (לא `crypto.randomUUID`, ADR-4).

## 4. `useHistory` ו-`App`

- `useHistory` שומר `results`, `loadError`, `saveError`, `deleteError`. טעינה אחת בעלייה.
- ב-`App`: Effect שמופעל כש-`state.status` הופך ל-`won`/`lost`. `ref` זוכר את ה-`gameId` האחרון שנשמר; אם זהה — לא עושה כלום. כך Strict Mode (Effect כפול), השהיה, מעבר מסכים ורענון (אין שמירה בכלל, כי המשחק לא נגמר) לא יוצרים כפילות. השמירה מיידית בסיום, לא אחרי השהיית הודעת הסיום (ADR-4).
- `saveError` מתאפס בתחילת משחק חדש (`gameId` חדש).

## 5. ממשק

**אודות** (`DESIGN` §1.2): תחת "10 המשחקים האחרונים" — כרטיסים מהחדש לישן. כל כרטיס: תאריך ושעה בעברית (`toLocaleString('he-IL')`, זמן מקומי), "הושלמו N שלבים" (בהתאם לעברית: "לא הושלם אף שלב" / "הושלם שלב אחד" / "הושלמו N שלבים"), ותגית "ניצחון" או "הפסד" עם הדגשה מאופקת בצבע. בלי רשומות: "עדיין אין משחקים שמורים." והכפתור לא מוצג. הרשימה גוללת בתוך העמוד.
**כפתור "מחק היסטוריה"** — רק כשיש רשומות; פותח `ConfirmDialog` (`role="dialog"`, `aria-modal`, שאלה **"למחוק את ההיסטוריה?"**, הסבר קצר "פעולה זו תמחק את כל התוצאות השמורות במכשיר.", כפתורי "ביטול" (משני) ו-"מחק" (אדום), סדר מתאים ל-RTL). "ביטול" ו-Escape סוגרים בלי שינוי. "מחק" ← `clear()`; בהצלחה — הדיאלוג נסגר והרשימה מתרוקנת עם החיווי הריק; בכשל — הדיאלוג נסגר, הרשימה נשארת, ומוצגת הודעה אדומה.
**הודעות שגיאה בעברית:** "לא ניתן לקרוא את ההיסטוריה השמורה." (טעינה, באודות), "לא הצלחנו לשמור את תוצאת המשחק." (שמירה, בחלונית הסיום בבית), "לא הצלחנו למחוק את ההיסטוריה." (מחיקה, באודות).
**החלטת ברירת מחדל:** התאריך מוצג בפורמט קצר (לדוגמה `25.10.2026, 13:45`) — הפורמט הסטנדרטי של הדפדפן לעברית, ללא ספריית תאריכים.

## 6. בדיקות

**יחידה (`historyStorage.test.ts`, `localStorage` מדומה):** ריק ← ריק; הוספה שומרת בראש; 11 הוספות ← 10 רשומות והישנה נעלמה; סדר חדש לישן; JSON פגום ← `ok:false` והוספה הבאה מתקנת; רשומות לא תקינות מסוננות; `localStorage` שזורק בקריאה/כתיבה/מחיקה ← כשל מדווח, בלי קריסה; `clearHistory` מרוקן.

**אינטגרציה (כמו ב-`App.game.test.tsx`: אותם Mocks ו-Fake Timers):**
- הפסד בשלב 1: רשומה אחת — "הפסד", 0 שלבים. ניצחון: "ניצחון", 10 שלבים.
- השהיה, מעבר ל"אודות" ובחזרה, הסתרת דף, ו"אישור" — לא מוסיפים רשומה. רנדר חדש של `App` באמצע משחק — אין רשומה.
- רנדר ב-`StrictMode` של משחק שהסתיים ← רשומה אחת.
- 11 משחקים ← 10 רשומות; הרשומות שורדות רנדר חדש של `App`.
- "מחק היסטוריה": לא מוצג בהיסטוריה ריקה; "ביטול" לא משנה; "מחק" מרוקן ומחזיר חיווי ריק.
- `localStorage` שזורק: המשחק ממשיך כרגיל, מוצגת הודעת שמירה נכשלה; מחיקה שנכשלה ← הרשימה נשארת והודעה מוצגת.
